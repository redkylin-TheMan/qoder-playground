一、背景与目标
烘干厂现场操作人员以中老年为主，在繁忙的收粮、卖农资过程中，选错客户、选错品种、称错重量
、金额填错 是高频错误。同时部分业务会 现场收取或支付现金，随后才生成对应的应收 / 应付账款。
本方案要同时达成三个目标：
1 业务好改：发现填错，现场操作员一键修改或作废，系统自动算账
2 资金安全：已发生的现金收付绝不凭空消失，账实始终相符
3 零财务负担：操作员不用懂财务，钱的事由系统通知财务处理
二、核心设计原则
整套方案建立在三条原则上：
原则一 业务层与资金层分离
现场操作员只负责「业务单」（数量 / 金额 / 品种 / 客户），改完系统自动调整库存与应收应付；「收 /
付款单」的任何变动一律交给财务处理。两拨人各管各的，互不卡壳——操作员改 /
作废业务单不需等财务、点即生效，只有其中收 / 付款单的变动由系统转交财务。
原则二 现金铁律
已经发生的现金收 / 付，不能凭空消失。业务单（出库 /
入库单）操作员照样能改、能作废，点即生效、绝不拦截；只是其中「收 /
付款单（钱）」这一步系统不让现场动，而是自动标记并通知财务，由财务去作废重建收 / 付款单。
原则三 一句话心智模型
操作员只需记住一句话：「业务错了我改 / 作废，钱的事系统会通知财务，我不用管。」

资金结算表）尚未调整、暂挂待核。通过三道防线确保财务及时处理、不漏账：
1 强提醒：财务端「异常单据」红点 + 待办列表，不可忽略
2 标记不消：直到财务作废重建收付款单，该单一直标红
3 对账高亮：资金结算表 / 客商账务里，未处理的纠错单标红置顶
实施说明：本节「收 / 付款单待复核、财务待办、对账标红」为方案的配套联动机制（部分规划中），分阶段
上线；在完整联动落地前，已收 / 付款单据的纠正可先由财务按通知手工作废重建收 /
付款单，业务单一侧的作废 / 修改不受影响、操作员照常即时操作。

九、什么时候用修改、什么时候用作废
两者都用于纠错，区别在于「错了一部分」还是「整单都不对」：
场景 用哪个 举例
数量 / 重量称错了 修改 净重录成 9000，实际 10000 → 改数量
单价 / 金额填错了 修改 单价多打一位，金额 ¥6200 应是 ¥620 → 改金额
品种选错了（同类） 修改 选成"深香优"，实际"竹两优" → 改品种
客户 / 供应商选错了 作废 给张三的单录成李四 → 整单作废，重录
整单作废不要了 作废 客户临时不卖了 / 重复录了一单 → 作废
粮食 / 农资 选错了 作废 本该农资入库录成粮食入库 → 作废重录
简单记：改个别字段（数量/金额/品种）用修改；换了人（客户/供应商）或整单不要了用作废。
十、底层留痕约定（资金与库存如何记录）
无论修改还是作废，系统对库存和账款的每一次变动都留痕、可追溯：
库存流水
每次库存变动写一行，记 变动量(带正负) / 变动前后 / 关联单号 /
操作人。作废、改单的库存调整也写新行，不删原记录。
客商台账 每笔业务写一条流水，是资金结算表的数据源。冲账用"负向新行"，不删原行。
资金结算表
把每条客商流水显示成一行。应付列(买粮+买农资入库应付−付款−抵种)、应收
列(卖粮+卖种+农资应收−收款−抵种)；另设农资预付款三列(预付充值/已使用/余
额，单独滚动、不计入应付应收)。应付余额滚动累计(正=厂欠客户,负=客户欠厂)
。
一句话：库存动一次写一条库存流水(带±)，账动一次写一条客商流水(冲账用负数)，资金结算表把每条都显
示成一行——原单不删、冲账另起一行，全链路可查。
